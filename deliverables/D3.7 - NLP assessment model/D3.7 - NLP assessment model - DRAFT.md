## Summary

D3.7 answers questions about SURIMI's data in ordinary language. Someone asks a plain
question. The model finds the figure, states it, and names the file it came from.

We evaluate the model against 68 questions from ten domain experts. SURIMI's servers can
answer 54 of them. The other 14 concern data SURIMI does not hold, where a refusal is the
correct answer.

The deployed model answers 24 of the 54 and correctly refuses 12 of the 14. It invented
nothing. Of the 30 it does not answer, 27 are refusals of questions the data supports and
3 are wrong.

## 1. Model purpose

D3.7 gives a person who cannot write SQL a number from SURIMI's data, with its source. The user
asks a question in their own words. The model picks the dataset, runs the query, and
returns the figure in a sentence with its source named.

Where the data does not support an answer, the model says so and states why. The
evaluation scores an unsupported answer more heavily against the model than a refusal.

The model does not run simulations, and it does not generate or execute user code. It
reads only what the two SURIMI servers publish, and no data the user supplies.

## 2. Inputs

The user gives the model one input: a question in natural language.

The model reads three sources. SURIMI services publish all three, and the user supplies
none of them.

- **Tabular observations.** 28 registered datasets cover EU Data Collection Framework
  economic and catch tables, OECD support estimates, ICES stock assessments, MEDITS survey
  CPUE and SURIMI's own tables.
- **Gridded model output.** NetCDF files and region masks, returned as pre-aggregated
  slices so raw grid cardinality never reaches the language model.
- **Documentation.** The public SURIMI documentation corpus answers questions of
  definition and method. The corpus excludes the internal development wiki.

## 3. Outputs

The model returns four things.

- An answer in plain language, stating the figure and naming its source.
- A receipt for every analytical figure, recording the query that produced it and the data
  it read.
- A refusal with a stated reason, where the served data does not support the question.
- A public audit page carrying all 68 evaluation questions. Each one shows the model's
  answer, the answer the data supports, the source files and the commands that reproduce
  its figures.

## 4. Objectives

The model should answer what SURIMI's data can answer, refuse what it cannot, and never
present an unsupported figure as fact.

### 4.1 How the model is evaluated

Eleven domain experts reviewed the assistant between August and September 2026 and filed
fifteen survey submissions. Ten of them contributed questions. We recorded each question
as they wrote it, then adjudicated it into one of four classes according to whether SURIMI
holds the data and whether a served tool reaches it.

We searched the raw data lake for every question and wrote down what it supports, before
any test. Each expected answer is published with its source files and a command that
reproduces its figures.

Each question is then put to the deployed system on its own, with no conversation before
it and no follow-up after.

### 4.3 Known limits

Twenty-seven refusals are the largest limit. The data is served in each case and the
answer reproducible, and the model does not retrieve it.

A stronger model reaches 31 of the 54 on the same servers with the same questions. Part of
the gap is the model on the chat and not the data behind it.

Verdicts are judgements made by a language model against the expected answer. Two runs of
the same evaluation agree on about 75 per cent of them, so a difference under about seven
questions is not evidence of a change.

Three questions open with a pronoun that has no antecedent when the question is asked on
its own, and cannot be answered as written.

The evaluation set is not tagged by deliverable, so this document reports one figure for
the model as a whole.

## Summary

D3.9 is the policy half of the same assistant described in D3.7: a manager or adviser asks
what a seasonal closure would do to a fleet, or which stocks a harvest control rule puts
below their limit, and gets an answer out of SURIMI's scenario output.

It runs on the same two servers, through the same chat, and is measured in the same
evaluation. The difference is the class of question, and that difference is the whole
result: thirteen of the 68 expert questions are policy questions, and none of them is
answered today.

This is not a language-model failure. Six of the thirteen are questions SURIMI could answer
if the run existed, and no client we have measured answers any of them, including one
substantially stronger than the deployed chat. The remaining seven are refused correctly,
because SURIMI holds no output to answer them from at all.

One model run is currently listed on the model server, a hindcast whose time axis ends in
January 2017. It carries no scenario description and no comparison case. A question of the
form "what changes if" has nothing to read.

## 1. Model purpose

The user is someone weighing options: a fisheries manager, a policy adviser, a Commission
desk officer. They want to compare a scenario against a baseline or against another
scenario, in the terms they work in (fleets, seasons, stocks, areas), without opening a
NetCDF file.

D3.9 reads runs that already exist. It does not run simulations, and a question that
requires a run nobody has performed is refused with the reason stated. That boundary is
deliberate. The alternative, a model that produces a plausible-looking projection from
historical data, is the single most damaging thing this component could do, because a
fabricated forecast in a fisheries advice chain is indistinguishable from a real one until
someone acts on it.

The evaluation is built to catch exactly that, and weights a fabricated answer more heavily
than a refusal.

## 2. Inputs

One input from the user: a policy question in natural language.

The model reads the sources described in D3.7 section 2, and one that is specific to it:

**Scenario output.** Gridded model results per run, with the species, fleet, market and
time axes needed to compare one run against another. The one real sample on record,
`westmed-2013-2017-biomass-catch-sales.nc`, covers the western Mediterranean from January
2013 to January 2017 across 49 monthly steps, 94 species, 9 fleets, 38 markets and 7 gear
types, on an 82 by 109 grid. It carries 21 variables including gross catch, live and dead
discards, biomass and price.

That file is the shape of what D3.9 needs. What is missing is a second one to compare it
against, and a description saying which policy each represents.

The historical baseline a scenario is judged against comes from the observed tables: EU DCF
catches and landings, which do cover the relevant fleets and years.

One trap is worth naming because it has already caused a wrong answer. The simulated sales
table runs from 2025 to 2040 and looks like a catch projection. It is not. `quantity_kt` is
quantity **sold**, excludes discards entirely, and is a market outcome. Modelled catch
output stops at the 2017 hindcast. The catalogue now carries that warning on the table
itself.

## 3. Outputs

- An answer in plain language, naming the run it came from.
- A comparison between runs, where more than one exists.
- A refusal with a stated reason, where no run supports the question.
- The same public audit page as D3.7, carrying every evaluation question with its answer
  and its sources.

## 4. Objectives

The model should answer a policy question from scenario output that exists, refuse one that
needs a run nobody has performed, and never present a projection it cannot support.

### 4.1 How the model is evaluated

The method is D3.7 section 4.1 and is not repeated here. The same eleven experts, the same
fifteen submissions, the same adjudication and the same expected answers established from
the raw data before testing.

Thirteen of the 68 questions ask for a scenario, a counterfactual or a forward projection.
Those thirteen are the subject of this section.

The six:

| | |
| --- | --- |
| Q-E1-8a, Q-E1-8b | Trawling revenues in Spain if fishing closes January to March |
| Q-E2-1a | How Belgian catches change with climate change |
| Q-E9-1 | Potential catches for key target species over the coming years |
| Q-E9-3 | Species in the red zone under this scenario's harvest control rules |
| Q-E3-7 | Which Gulf of Lion areas to protect, and how strictly |

Q-E1-8a is the clearest case. SURIMI does hold the historical baseline: Spanish trawl
landings value in January to March averages 21.7 per cent of the annual total over twelve
years, with a standard deviation of 2.8 points, from 1.29 million Spanish rows in
`EU_DCF_Catches.csv`. What it cannot do is say what happens to revenue when those months
are closed, because that requires POSEIDON or an equivalent to be run and no such run
exists.

### 4.3 Known limits

The limit is the absence of scenario output, and it is not one this component can close
from its own side. Five of the six unanswered questions need a simulation that has not been
performed. No amount of cataloguing or prompt work reaches them.

Q-E3-7 is different and worth separating. It asks which areas of the Gulf of Lion to
protect and how strictly, which requires an objective function and a solver. Nothing in the
SURIMI stack performs optimisation. Whether it should is a consortium modelling decision,
not a gap in this module, so we flag it and make no claim on it.

The strongest client we measured reaches none of the six either, which rules out the chat
model as the cause.

Verdict reliability is as described in D3.7 section 4.3: about 75 per cent agreement
between runs, and no claim here rests on a difference smaller than the noise. The zeros in
the table above are not close calls.

The evaluation set is not tagged by deliverable. The thirteen policy questions were
identified by reading all 68, and a reviewer may reasonably draw that line in a different
place. The six named above are the ones where the boundary is unambiguous.
